# สร้างยอดสรุปรายวัน (dailyStats) ย้อนหลัง — ทำครั้งเดียว

หน้าสถิติ (แท็บยอดขาย วัน/สัปดาห์/เดือน/ปี) อ่าน "สรุป 1 doc ต่อวัน" แทนการอ่านออเดอร์ทุกใบ
แอปสร้างสรุปเองตอนต้องใช้อยู่แล้ว — สคริปต์นี้แค่สร้างของวันเก่าทั้งหมดไว้ก่อนในครั้งเดียว
เครื่องแรกที่เปิด "ปี" จะได้ไม่ต้องอ่านออเดอร์ย้อนหลังทั้งหมด

- สร้างเฉพาะวันที่ปิดแล้ว (เก่ากว่าเมื่อวาน) — วันนี้/เมื่อวานแอปอ่านสดเสมอ
- วันที่ยังมีออเดอร์ค้าง (รอชำระ/กำลังเตรียม) ข้าม — แอปสร้างเองเมื่อปิดบิลแล้ว
- ไม่แตะออเดอร์เลย (อ่านอย่างเดียว) เขียนแค่ collection `dailyStats`
- รันซ้ำได้ — วันที่มีสรุปที่ใช้ได้แล้วข้าม

## ก่อนเริ่ม: วาง rules ของ dailyStats ใน Firebase Console

Firestore → Rules → เพิ่มก้อนนี้ไว้ก่อน `}` สองตัวสุดท้าย (ตรงกับ `firestore.rules` ใน repo) → Publish

```
    match /dailyStats/{day} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && day.matches('^[0-9]{4}-[0-9]{2}-[0-9]{2}$');
    }
```

## ขั้นตอน (terminal ที่โฟลเดอร์โปรเจกต์ — ทำเวลาร้านปิด)

### 1. ดูก่อน (ไม่เขียนอะไร)

```
npm run stats:dry-run
```

ถามรหัสผ่านพนักงาน (รหัสเดียวกับหน้าล็อกอินในแอป ตัวอักษรไม่ขึ้นบนจอ) แล้วแสดง:
จำนวนวัน, ออเดอร์ที่อ่าน, ยอดรวม/เงินสด/โอน, doc ใหญ่สุด, วันที่ข้าม

reads ≈ จำนวนออเดอร์ทั้งหมด (ครั้งเดียว)

### 2. เขียนจริง

```
npm run stats:apply
```

รหัสผ่าน → สรุปอีกรอบ → พิมพ์ `yes` → รอจนขึ้น `เสร็จ: เขียนสรุป ... วัน`

### 3. ตรวจในแอป

เปิดหน้าสถิติ → ยอดขาย → ปี / เดือน — ตัวเลขต้องเท่าเดิม

## เมื่อไหร่ต้องรันใหม่

- แก้ออเดอร์เก่าตรงๆ ใน Firebase Console (แอปไม่รู้) → `npm run stats:apply -- --rebuild`
- การแก้จากในแอป (บันทึก/ยกเลิกบิลย้อนหลัง) ไม่ต้อง — แอปตีสรุปวันนั้นว่าเก่าและคำนวณใหม่เอง

## ลองกับ emulator บนเครื่อง (ไม่แตะร้านจริง)

```
npm run stats:dry-run -- --emulator
npm run stats:apply -- --emulator
```

ต้องเปิด emulator ก่อน (ดู `tests/rules/preview-seed.mjs`)
