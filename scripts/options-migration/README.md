# แปลงตัวเลือกในตัว → กลุ่มตัวเลือกที่สร้างเอง

สคริปต์ชุดนี้แก้ข้อมูล `menuItems` ของร้านจริง (production) ทำเฉพาะเวลาร้านปิด หลัง deploy เว็บและติดตั้ง APK ใหม่แล้ว
(ลำดับดูหัวข้อสุดท้าย)

สิ่งที่ทำ: ตัวเลือกในตัว (เนื้อ/เผ็ด/ขนาด/ไข่ดาว/จาน-ช้อน-แก้ว) → กลุ่มตัวเลือก, เอาค่าเริ่มต้นออกทุกกลุ่ม,
ติ๊ก "แสดงในหน้าจัดการเมนู" ให้กลุ่มเนื้อสัตว์, ตัวเลือกที่ซ่อนอยู่ → ปิด, ลบเมนูตัวอย่างเก่า 18 รายการ (a1–s2)
แก้เฉพาะ field ตัวเลือก — ราคา/ชื่อ/สถานะขาย/สต็อก/รูป ไม่แตะ

ไฟล์สำรองเก็บที่ `scripts/options-migration/backups/` (ไม่อยู่ใน git) — ห้ามลบจนกว่าจะแน่ใจว่าไม่ต้องย้อนกลับ

## ขั้นตอน (เปิด terminal ที่โฟลเดอร์โปรเจกต์ แล้วพิมพ์ทีละบรรทัด)

### 1. ดูก่อนว่าจะเปลี่ยนอะไร (ไม่เขียนอะไรเลย ไม่ต้องล็อกอิน)

```
npm run options:dry-run
```

สคริปต์สำรองเมนูทั้งหมดลงไฟล์ก่อน แล้วแสดงรายการว่าเมนูไหนได้กลุ่มอะไร ราคาเท่าไหร่
อ่านแล้วถ้าถูกต้อง ไปขั้นที่ 2 — ถ้ามีบรรทัด `!!! พบปัญหา` ให้หยุดแล้วส่งข้อความนั้นมาดู

### 2. แปลงจริง

```
npm run options:apply
```

1. สคริปต์สำรองใหม่อีกรอบ + แสดงรายการเดิมอีกครั้ง
2. ถาม `พิมพ์ yes เพื่อเริ่ม` → พิมพ์ `yes` แล้วกด Enter
3. ถาม `อีเมล:` → พิมพ์อีเมลพนักงาน (อันเดียวกับที่ล็อกอินในแอป) กด Enter
4. ถาม `รหัสผ่าน:` → พิมพ์รหัส (ตัวอักษรจะไม่ขึ้นบนจอ เป็นเรื่องปกติ) กด Enter
5. รอจนขึ้น `เสร็จ: แปลง/ลบ ... | ข้าม ...`

ถ้ามีเมนู "ข้าม" เพราะมีคนแก้ระหว่างรัน — รัน `npm run options:apply` ซ้ำได้เลย (เมนูที่แปลงแล้วจะไม่ถูกแตะ)

### 3. ตรวจในแอป

เปิดหน้าจัดการเมนู: เมนูเนื้อสัตว์มีปุ่มเปิด/ปิดด่วน, เนื้อ (ข้าวซอยไข่ออนเซ็น/แกงอ่อม) ขึ้นหมด, เปิดหน้าแก้ไขเมนูดูตัวเลือก
เปิดหน้าลูกค้า (สแกน QR) ลองดูเมนูที่มีไข่ดาว/ความเผ็ด ราคาต้องเท่าเดิม

### ย้อนกลับ (ถ้าจำเป็น)

```
npm run options:rollback
```

ใช้ไฟล์สำรองล่าสุดเอง ถาม `yes` + อีเมล/รหัสผ่านเหมือนขั้นที่ 2
คืนเฉพาะตัวเลือก (ราคา/สถานะขายที่แก้หลังแปลงยังอยู่) และสร้างเมนูตัวอย่างที่ลบไปกลับคืน
อยากใช้ไฟล์อื่น: `npm run options:rollback -- scripts/options-migration/backups/<ชื่อไฟล์>.json`

## ลำดับที่ปลอดภัยที่สุด

1. **deploy เว็บ** (`npm run deploy`) — โค้ดใหม่อ่านข้อมูลแบบเดิมได้ (แปลงตอนอ่าน) ลูกค้าเห็นตัวเลือกเป็นปุ่มแบบใหม่ทันที ราคาเท่าเดิม
2. **build + ติดตั้ง APK ใหม่ทุกเครื่อง** — แอปเก่าใช้กับข้อมูลทั้งแบบเดิมและแบบแปลงแล้วได้ แต่ปุ่มด่วนขึ้นแค่กลุ่มเนื้อสัตว์
   และพนักงานที่สั่งแทนลูกค้ายังเลือกตัวเลือกที่ปิดของกลุ่มอื่นได้
3. **หลังร้านปิด: dry-run → apply** (ขั้นตอนข้างบน)

ถ้าข้ามขั้น 3 ไปก่อนก็ไม่พัง: เมนูไหนถูกแก้/กดเปิดปิดตัวเลือกจากแอปใหม่ จะถูกแปลงลง DB เองทีละเมนู
