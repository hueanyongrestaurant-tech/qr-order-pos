# ลบรูป (base64) ที่ฝังอยู่ในออเดอร์เก่า

ออเดอร์ก่อน 11 ก.ย. 2026 เก็บรูปเมนูทั้งรูปไว้ในทุกรายการ ทำให้หน้าประวัติ/สถิติโหลดช้า
(ส่วนวิเคราะห์ "ทั้งหมดที่ผ่านมา" ต้องดาวน์โหลดทุกออเดอร์ตอนเปิดครั้งแรกบนแต่ละเครื่อง)
สคริปต์นี้เปลี่ยนรูปในรายการเป็นค่าว่าง เหมือนออเดอร์ใหม่ทุกใบ — หน้าประวัติ/สถิติ/ใบเสร็จไม่ได้ใช้รูปนี้

แก้เฉพาะช่องรูปในรายการ (`items[].item.photo` ที่ขึ้นต้นด้วย `data:`) — ราคา จำนวน สถานะ เวลา และข้อมูลอื่นไม่แตะ
ออเดอร์ที่มีคนแก้หลังสำรอง → ข้าม ไม่เขียนทับ

ไฟล์สำรองเก็บที่ `scripts/order-photos-migration/backups/` (ไม่อยู่ใน git) — เก็บไว้จนกว่าจะแน่ใจว่าไม่ต้องย้อนกลับ

ทุกขั้นต้องใช้รหัสผ่านพนักงาน (ออเดอร์อ่านได้เฉพาะพนักงาน) — ทำเวลาร้านปิด

## ขั้นตอน (เปิด terminal ที่โฟลเดอร์โปรเจกต์ แล้วพิมพ์ทีละบรรทัด)

### 1. ดูก่อนว่าจะเปลี่ยนอะไร (ไม่เขียนอะไรเลย)

```
npm run photos:dry-run
```

1. ถาม `รหัสผ่านพนักงาน` → พิมพ์รหัสเดียวกับหน้าล็อกอินในแอป (ตัวอักษรไม่ขึ้นบนจอ เป็นเรื่องปกติ) กด Enter
2. รออ่านออเดอร์ทั้งหมด (หลายนาที — ออเดอร์เก่าหนัก)
3. ขึ้นสรุป: จำนวนออเดอร์ที่มีรูป, ช่วงวันที่, ขนาดก่อน → หลัง

### 2. ลบรูปจริง

```
npm run photos:apply
```

1. รหัสผ่านพนักงาน → สำรองใหม่อีกรอบ + สรุปอีกครั้ง
2. ถาม `พิมพ์ yes เพื่อเริ่ม` → พิมพ์ `yes` กด Enter
3. รอจนขึ้น `เสร็จ: ลบรูปแล้ว ... | ข้าม ...`

ถ้ามี "ข้าม" เพราะมีคนแก้ระหว่างรัน — รัน `npm run photos:apply` ซ้ำได้เลย (ออเดอร์ที่ลบแล้วจะไม่ถูกแตะ)

### 3. ตรวจในแอป

เปิดหน้าประวัติวันเก่า (เช่น ต้นเดือน ก.ย.) — ยอด รายการ ตัวเลือก ต้องเหมือนเดิม และโหลดเร็วขึ้น

### ย้อนกลับ (ถ้าจำเป็น)

```
npm run photos:rollback
```

ใช้ไฟล์สำรองล่าสุดเอง ถาม `yes` + รหัสผ่านพนักงาน ใส่รูปกลับเฉพาะรายการที่รูปยังว่างอยู่
อยากใช้ไฟล์อื่น: `npm run photos:rollback -- scripts/order-photos-migration/backups/<ชื่อไฟล์>.json`
